# Proposed architecture and trust boundaries
Production primary -> read replica -> restricted extraction runner -> encrypted restricted holding area -> automated masking -> SQL expert technical review -> authorised privacy review -> approved SQL fixture library -> developer local PostgreSQL. Only authorised roles access raw extracts; logs must not expose payloads. Protect encryption keys, use short retention, audit access, prevent uncontrolled onward sharing. For Tonic's common database-to-database path, a temporary destination may still be necessary; it is not equivalent to direct SQL export. A dump generated from destination does not remove destination requirement. A cloud trial with fabricated data is a separate test architecture.
